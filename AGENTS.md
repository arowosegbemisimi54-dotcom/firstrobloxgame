# Project instructions

## Changes to the user's game notes

Treat revised notes as incremental changes, not a request to rebuild or redesign
existing features. Compare them with the last accepted notes and implementation.
Implement only newly added requirements and explicitly changed details.

Preserve all other behavior, visuals, text, layout, assets, settings, and code.
Do not introduce unrelated fixes, refactors, cleanup, restyling, or enhancements
unless the user instructs you to do so. Repeated requirements are context, not
authorization to change working features. An omitted detail alone does not
authorize its removal.

Make only the supporting edits necessary for the requested change. If completing
it would require changing another established feature, explain the dependency
and obtain the user's instruction before changing that feature. When a difference
is ambiguous, clarify it rather than guessing at a redesign.

Apply this rule throughout the Shirts and Skins project unless the user explicitly
revises it. In completion reports, identify the specific requested differences
implemented.
